# Building the Windows installer

This turns TweetDelete into a normal Windows app: a Start Menu entry and
optional desktop icon that launch a system tray app, which starts the local
server in the background and opens your default browser to it automatically.
No Python installation is required on the end user's machine — PyInstaller
bundles a private copy of Python plus every dependency into the build, so it
never touches, checks, or depends on anything already installed.

This only needs to be done once per release, on a Windows machine (I can't
produce a tested Windows binary myself from this environment — PyInstaller
doesn't support cross-compiling from Linux to Windows). Everything below
runs entirely on your machine.

## What gets built, and how it fits together

```
tray_app.py          entry point — shows the tray icon, starts server.py in
                      a background thread, opens the browser, opens the
                      help PDF from the tray's Help menu item
server.py            same local server used in the plain/dev version
build.spec            PyInstaller build recipe (bundles public/ + icon.ico)
public/
  TweetDelete for Windows.pdf   help guide — you add this file (see below);
                                linked from the app footer, the tray Help
                                menu, and opened automatically post-install
packaging/
  requirements.txt    build-time Python packages (pystray, Pillow, PyInstaller)
  icon.ico            app icon, already generated — used for the tray icon,
                       the .exe itself, and Start Menu/desktop shortcuts
  make_icon.py         (optional) regenerates icon.ico if you want to customize it
  installer.iss        Inno Setup script that wraps the PyInstaller output
                       into a proper installer with an uninstaller
```

`pyinstaller` builds `dist/TweetDelete/TweetDelete.exe` (a *folder* of files,
not a single .exe — deliberately, see the comment at the top of
`build.spec` for why). `installer.iss` then packages that whole folder
behind one Start Menu shortcut and one optional desktop shortcut.

One layout detail worth knowing: PyInstaller 6.x's onedir builds put
everything except the main `.exe` — including the bundled `public/` folder
— inside a `_internal\` subfolder (`dist\TweetDelete\_internal\public\...`),
not directly next to the exe. `server.py` already resolves this correctly
at runtime, and `installer.iss`'s post-install help-PDF step is written to
match it. If you ever add another `[Run]`/`[Icons]` entry that points at a
bundled data file, remember to include `_internal\` in that path too.

## Adding the help guide

Drop your finished PDF into `public/` and name it exactly:

```
public/TweetDelete for Windows.pdf
```

That's the only correct location — not `dist/`, since `dist/` is fully
deleted and regenerated by every `python -m PyInstaller build.spec` run, so anything
placed there manually is lost on the next build. `public/` is the single
folder both PyInstaller (via `build.spec`'s existing `('public', 'public')`
data mapping) and the local server already treat as the one source of
truth, so placing it there means it flows through automatically:

- The **web app footer** links straight to it as a normal static file.
- The **tray icon's Help menu item** opens it with the system's default PDF
  viewer (`os.startfile`), reading it from the same bundled `public/` folder.
- The **installer** shows it as a checked-by-default "View the TweetDelete
  help guide" option on the finish page, right alongside "Launch
  TweetDelete" — so it opens automatically right after install unless the
  user unchecks it.

No changes to `build.spec` or the PyInstaller step are needed — just add
the file and rebuild normally. If the file is missing when you build, the
installer and tray Help menu won't error, but clicking them won't open
anything either (the tray app logs a warning to `tweetdelete.log` in that
case) — so double check it's there before you ship a build to anyone.

## One-time setup on your Windows machine

1. **Install Python 3.11+** from [python.org](https://www.python.org/downloads/windows/)
   if you don't already have it. During install, tick **"Add python.exe to PATH"**.
2. **Install Inno Setup 6** (free) from [jrsoftware.org](https://jrsoftware.org/isinfo.php).
   Default install options are fine.
3. Open **Command Prompt** or **PowerShell**, and `cd` into the `tweetdelete`
   project folder (the one containing `server.py`, `tray_app.py`, `build.spec`).

## Every time you build a new version

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r packaging\requirements.txt
```

Then build the app. Use `python -m PyInstaller` rather than the bare
`pyinstaller` command — pip frequently installs the standalone
`pyinstaller.exe` script into a folder that isn't on your PATH (you'll see
a warning about this during the `pip install` step if so), which means
`pyinstaller build.spec` can silently fail to run at all while looking like
it worked. `python -m PyInstaller` always finds the right module regardless
of PATH, since it asks your active Python directly rather than relying on a
separate script being discoverable:

```powershell
python -m PyInstaller build.spec
```

This creates `dist\TweetDelete\TweetDelete.exe` plus its supporting files.
**Test it directly before packaging further:** double-click
`dist\TweetDelete\TweetDelete.exe`. You should see a small tray icon appear
near the clock, and your default browser should open to the app. Right-click
the tray icon to confirm "Open TweetDelete" and "Quit" both work, and that
launching it again while it's already running just re-opens the browser
instead of starting a second copy.

If anything goes wrong at this stage and no window/tray icon appears, check
`%LOCALAPPDATA%\TweetDelete\tweetdelete.log` — the app logs there instead of
a console window, since it's a windowed (no-console) build.

Once that works, build the installer:

```powershell
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" packaging\installer.iss
```

(Or open `packaging\installer.iss` in the Inno Setup Compiler app and click
**Compile** — same result.) This produces:

```
packaging\installer_output\TweetDelete-Setup.exe
```

That's the file you'd hand to someone to install the app.

## Installing it

Double-click `TweetDelete-Setup.exe`. Because it's set to
`PrivilegesRequired=lowest`, it installs to
`%LOCALAPPDATA%\Programs\TweetDelete` for your user account only, with **no
UAC/admin prompt**. It adds a Start Menu entry and (if you tick the box
during install) a desktop icon, plus a normal entry under **Settings → Apps**
for uninstalling later.

After install, launching from the Start Menu or desktop icon should: show
the tray icon, open your browser to the app, and behave exactly like running
`dist\TweetDelete\TweetDelete.exe` directly did.

## Two things to expect and how to handle them

- **Windows SmartScreen warning.** Since this isn't code-signed, first
  launch of the installer (and possibly the app itself) will show "Windows
  protected your PC." Click **More info → Run anyway**. This is expected for
  any unsigned app and isn't a sign of a broken build. Getting rid of it
  requires a paid code-signing certificate (~$70–400/year) — only worth it
  if you plan to distribute this beyond yourself.
- **Antivirus false positives are possible but less likely than with
  --onefile builds**, since this uses one-folder mode specifically to avoid
  the self-extraction pattern that trips AV heuristics. If your AV still
  flags it, that's a false positive on an unsigned/uncommon binary, not a
  sign anything is actually wrong — you can verify by checking
  `tweetdelete.log` for normal startup messages.

## Uninstalling

Use **Settings → Apps → TweetDelete → Uninstall**, or the "Uninstall
TweetDelete" shortcut in the Start Menu folder. The uninstaller tries to
close the tray app first automatically (so Windows can delete the running
.exe) — **this specific step hasn't been verified on a live Windows
machine yet**. If uninstall ever reports it couldn't remove
`TweetDelete.exe`, right-click the tray icon → **Quit** first, then run
uninstall again.

## Regenerating the icon (optional)

`packaging/icon.ico` is already built and checked in — you don't need to
touch this unless you want a different icon. If you do:

```powershell
pip install Pillow
python packaging\make_icon.py
```

This overwrites `packaging/icon.ico`. Re-run the PyInstaller and Inno Setup
steps above afterward to pick up the change.

## What's next: Ubuntu

Once this is working end-to-end on Windows, the Ubuntu path is
architecturally simpler — no PyInstaller bundling is needed since Debian/
Ubuntu systems reliably ship Python 3 already, and `apt` handles dependency
declaration natively. That'll be a `.desktop` launcher entry plus a small
`debian/` control/packaging directory built with `dpkg-deb`, producing a
normal `.deb` installable with `sudo apt install ./tweetdelete.deb` or via
a PPA. Say when you're ready and I'll build that the same way.
